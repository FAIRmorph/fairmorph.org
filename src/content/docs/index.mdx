**Good field data are not automatically reusable data.** Researchers still need to connect observations, explain field meanings and missing values, check transformations and document their decisions. FAIRmorph aims to make that work easier without taking scientific judgment away from researchers. [Read the research background and project concept](/guide/overview/).

**Public benefit, grounded in research:** Studies document barriers to reusing archived ecological data and putting FAIR principles into practice ([Roche et al., 2015](https://doi.org/10.1371/journal.pbio.1002295); [Jantzen & Vriend, 2026](https://doi.org/10.1016/j.ecoinf.2026.103712)). FAIRmorph aims to help make existing—including publicly funded—research data more useful for biodiversity science, environmental monitoring and conservation, while reducing repeated data-preparation work. **Its impact will be evaluated through practical user testing.** [Why this matters](/guide/prototype-fund/#gesellschaftlicher-nutzen--wissenschaftlich-begrundet).

## From scattered data work to guided, reusable curation

![Two workflows for ecological data curation: conventional work often involves Python or R scripts, manual configuration and field mapping, specialist data-curation knowledge, and repeated cleanup; FAIRmorph aims to combine original data, guided scientific review, versioned decisions and verifiable RUNs.](/img/curation-workflows.svg)

*Conceptual comparison:* Python/R scripts, manual configuration and expert field mapping are **common challenges, not universal requirements**. FAIRmorph already supports source preservation, selected technical transformations and verifiable RUNs; **guided no-code scientific review and general-purpose standards-based exports remain development goals**. See the [research evidence](/guide/overview/#research-evidence-the-fair-implementation-gap) and [implementation status](/guide/prototype-fund/).

## What FAIRmorph aims to make easier

<CardGrid>
  <Card title="Bring ecological data together" icon="share">
    Keep original files intact while connecting observations, counts and related records through explicit, repeatable transformations.
  </Card>
  <Card title="Explain scientific meaning" icon="document">
    Make field definitions, units, methods and the difference between zero and missing values clear through guided, reviewable questions.
  </Card>
  <Card title="Check and trace decisions" icon="approve-check">
    See what changed, inspect validation results and retain versioned processing evidence instead of relying on undocumented spreadsheet edits.
  </Card>
  <Card title="Prepare data for reuse" icon="list-format">
    Carry context and provenance forward so colleagues can understand results and supported exchange formats can be prepared from verified data.
  </Card>
</CardGrid>

**The guided, no-code scientific workflow is the product goal, not an implemented end-to-end feature.** The Engine already supports selected operations, field-definition revisions and verified RUNs; the Workbench currently exposes a narrower technical workflow. [Scientific safeguards and architecture](/guide/overview/#transparent-versioned-and-reproducible-by-design).

## What works today?

| Area | Demonstrated in the proof of concept | Still to build or verify |
| --- | --- | --- |
| **Engine** | Unchanged source imports, selected declarative transformations, versioned reviews and verifiable RUNs. | Broader guided scientific workflows and production-scale reliability. |
| **Workbench** | Local project setup, file import, technical pipeline runs, result inspection and integrity checks. | Accessible field-mapping interviews and general-purpose publication workflows. |
| **Real-data checks** | Independent [CS-PHOC validation](/validations/docs/cs-phoc-reproduction-and-results/) against **16,940 recorded category values**; dataset-specific test exports. | Scientific approval and general-purpose exports directly from the Workbench. |
| **Distribution** | [v0.1.1](https://github.com/FAIRmorph/fairmorph-workbench/releases/tag/v0.1.1) automatically packages the bundled Engine for Windows and Linux. Linux packages and Windows portable startup were manually checked. | Full desktop acceptance testing and operational hardening; a brief [Windows console flash](https://github.com/FAIRmorph/fairmorph-workbench/issues/17) remains open. |

**Technical validation is not scientific approval.** The [Prototype Fund application and development plan](/guide/prototype-fund/) distinguishes implemented evidence from the intended six-month product development.
