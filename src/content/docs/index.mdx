## Less repeated work. More reusable research data.

When a dataset needs to serve a biodiversity network, a data repository, a project archive, or a collaborator, each destination may expect different files, terminology, and metadata. Preparing every version manually takes time—and repeating those steps after every correction makes results harder to compare and audit.

**FAIRmorph's goal is to separate the original observations from their scientific interpretation and destination-specific formatting.** Curate the source once, keep the decisions explicit, and reuse that documented work for different outputs and future dataset revisions.

<CardGrid>
  <Card title="One source, multiple destinations" icon="share">
    Prepare the same reviewed observations for different **formats and repository requirements**, rather than maintaining separate manual conversions for each destination. Darwin Core Archives, tabular data packages, and repository-specific submissions are part of the intended workflow.
  </Card>
  <Card title="Repeat updates consistently" icon="setting">
    When records are corrected or new observations arrive, reuse versioned definitions and transformations. Produce a new, traceable output without guessing which spreadsheet steps were used last time.
  </Card>
  <Card title="Know exactly what changed" icon="list-format">
    Preserve original files, explicit mapping decisions, run configurations, and integrity evidence. Compare releases and distinguish a **technically verified** transformation from a **scientifically approved** interpretation.
  </Card>
</CardGrid>

## One curation workflow, many outputs

**An illustrative research workflow:** Imagine a field team maintaining recurring wildlife surveys with observations, site information, counts, and photographs. A publication might require a Darwin Core Archive; a data repository might need a structured table and descriptive metadata; collaborators might need a GeoJSON overview.

<CardGrid>
  <Card title="1. Import and interpret" icon="document">
    Keep the source files unchanged. Explain what each field means, how units and missing values work, and which mappings are supported by the research methods.
  </Card>
  <Card title="2. Review and transform" icon="approve-check">
    Version the decisions, run a defined transformation, and retain checksums, output files, and a reproducible execution record.
  </Card>
  <Card title="3. Prepare target formats" icon="document">
    Use the **same curated data and provenance** as the basis for distinct output packages, with destination-specific schemas and metadata.
  </Card>
  <Card title="4. Update and repeat" icon="setting">
    On the next survey release, apply the reviewed configuration to the new source revision, verify the outputs, and document what changed.
  </Card>
</CardGrid>

**The benefit:** different representations of the same research observations can remain consistent, attributable, and easier to update. Publication, repository acceptance, and DOI assignment still require the relevant repository's own submission and review process.

## Designed for real field-data challenges

<CardGrid>
  <Card title="Keep sensitive data under local control" icon="shield">
    The Engine runs locally and preserves original source bytes. Researchers can work with unpublished observations and sensitive species locations without a mandatory cloud-processing service.
  </Card>
  <Card title="Reduce specialist software overhead" icon="laptop">
    The Workbench aims to make curation tasks accessible through a desktop interface. Its current proof of concept already supports project creation, file import, technical pipelines, RUN inspection, and verification; complete scientific mapping workflows remain in development.
  </Card>

## What works today?

FAIRmorph is in active development at **framework v0.13 (technical proof of concept)**. The vision of a fully integrated, one-click, multi-repository publishing workflow is **not yet a released product**.

What has been demonstrated:

- **Engine:** local import of unchanged source files, selected generic transformations, versioned review structures, verified RUN evidence, and technical integrity checks.
- **Workbench:** a local desktop workflow for project setup, explicit source import, technical pipeline selection/execution, project verification, and dataset-title revisions.
- **Real-data validation:** the original CS-PHOC seal-census dataset was used for a bounded reproducibility test. From the verified Engine run, **dataset-specific validation code** generated and independently audited Darwin Core Archive, PANGAEA-preparation TSV, and GeoJSON **test outputs**.

The CS-PHOC demonstration shows that several representations of the **same real data** can be prepared and checked against a common source. It does **not** yet prove generic publication export for arbitrary datasets, publisher acceptance, a completed Workbench publishing workflow, or scientific approval of the source-field drafts.
